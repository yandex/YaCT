# YaCT (Yet Another Closed-loop Teleoperation)

Open-source inference stack for Unitree G1 whole-body teleoperation.
The [project page](https://yandex.github.io/YaCT/) describes the method and shows
hardware results.

## Requirements

- Linux, macOS, or Windows with WSL2 (run the commands in the Linux shell)
- Python 3.10 or newer
- Docker
- For the default GPU image: an NVIDIA GPU, working `nvidia-smi`, and the
  NVIDIA Container Toolkit

On a machine without an NVIDIA GPU, use the CPU Docker path below.

## Quick start (NVIDIA GPU)

```bash
git clone https://github.com/yandex/YaCT.git
cd YaCT
./yact setup
./yact sim --view
```

Inference assets are versioned directly in the repository; Git LFS is not
required. Run `./yact setup` to verify that the checkout is complete.

Run commands from the repository root with `./yact`; installing the Python
package is not required. Optionally, `pip install -e .` installs the two host
CLI dependencies (`pyyaml` and `paramiko`) and adds `yact` to your `PATH`.

When invoked as `./yact`, the launcher can create a local `.venv` and install
those host dependencies. Skip this with `YACT_NO_VENV=1`, or auto-accept it with
`YACT_AUTO_VENV=1` for CI and scripts.

## CLI

Commands below use `./yact` from the repo root; after `pip install -e .`, drop the `./` prefix.

| Command | Purpose |
|---------|---------|
| `./yact setup` | Check toolchain, assets/, ensure g1-sim image |
| `./yact docker build g1-sim` | Ensure sim image (user layer → pull/build base) |
| `./yact docker pull g1-sim` | Pull base image + build user layer |
| `./yact docker run g1-sim` | Start long-lived container (optional; `./yact sim` starts it automatically) |
| `./yact docker stop g1-sim` | Remove container |
| `./yact docker shell g1-sim` | Interactive shell in container |
| `./yact docker exec g1-sim -- <cmd>` | Run command in container |
| `./yact sim` | MuJoCo sim — starts container if needed (`deploy`, WASD + QE; manual FSM progression) |
| `./yact deploy -n <iface>` | Real robot deploy (g1-sim container) |
| `./yact deploy -n <iface> --vr` | VR deploy in g1-sim container (Vuer WebXR) |
| `./yact version` | Package version |

**Sim (docker, recommended):**

```bash
./yact setup
./yact sim                # starts g1-sim container automatically if needed
./yact sim --view         # live browser preview; WASD + QE in browser (click page to focus)
./yact sim --view --no-wait --auto-next-node   # start and advance automatically (CI / scripting)
./yact sim --view --vr           # live VR via Vuer WebXR; prints an https URL to open in the headset browser
./yact sim --vr-replay trajectories/walk_forward.json --view   # scripts/generate_walk_trajectory.py
```

By default, simulation starts in **Damp** and waits for manual FSM progression.
Press `1` (or VR **B**) once per stage: **Damp → StartState → JustStand → Middle → DoTeleop**.
Motion control takes effect in **DoTeleop**. `--no-wait` only skips the browser Start
gate; use `--auto-next-node` to advance through the FSM automatically.

**WASD + QE keyboard control:** this is velocity control, not direct joint control.
It moves the policy's virtual head-and-hands target as a rigid pose, and the
policy makes the robot follow it. `W` / `S` move forward / backward, `A` / `D`
strafe left / right, and `Q` / `E` turn left / right (yaw). Forward and strafe
directions rotate with the commanded heading, so after turning, `W` continues in
the new facing direction.

With `--view`, click the browser page and **hold** keys to move; releasing all
movement keys stops the command, and combinations such as `W` + `A` work. Without
`--view` (including real-robot `--wasd`), press keys in the terminal running YaCT:
each press selects a persistent velocity.

> **Important:** terminal keyboard commands are latched on both the real robot and
> the simulator. Releasing `W`, `A`, `S`, `D`, `Q`, or `E` does **not** stop the
> motion—the robot or simulation keeps executing that command until you press
> **Space**. Another movement key changes the command but does not stop it.

Keyboard motion takes effect in the `DoTeleop` FSM node; `x` always requests
emergency damping.

**VR (`--vr`):** starts a [Vuer](https://github.com/vuer-ai/vuer) WebXR server and
prints an `https://<lan-ip>:8012` URL. On a headset on the same LAN, open that URL
in the browser, accept the self-signed cert warning once, then click *Passthrough*.
Head + motion-controller (Quest/Touch) poses stream back to the sim; the right
controller's A/B buttons drive the FSM. Hand tracking is not supported yet. The
TLS cert is autogenerated on first run (cached under `tmp/vuer_certs/`).

For manual work inside the container: `./yact docker shell g1-sim` (container must be running;
`./yact sim` or `./yact docker run g1-sim` will start it).

**Sim (no NVIDIA GPU — macOS / Windows with WSL2):**

```bash
./yact setup --no-docker --no-gpu
./yact sim --cpu --view         # builds/starts the CPU + OSMesa image
```

The setup command verifies Docker and the assets without preparing the GPU
image; `sim --cpu` then prepares the `g1-sim-cpu` image. This path is functional
but slow because both inference and rendering run on the CPU. It builds on Apple
Silicon and does not include CUDA. On Windows, install Python inside WSL2 and
enable Docker Desktop integration for that distribution; native Windows Python
is not supported.

## Real-robot deploy — step by step

Deploy runs the teleoperation policy in the **g1-sim container** on your PC and drives the G1
over Ethernet (CycloneDDS). Fast-LIO localization runs in a separate **lio container on
the robot's Jetson**, launched over SSH.

> For initial runs, suspend the robot and keep the area clear. `x` — or the VR **A** button
> — is the **e-stop**: it drops the robot to damping immediately. Keep the deploy terminal
> focused so keystrokes reach the FSM.

### 1. One-time setup (per machine)
```bash
./yact setup                     # toolchain and asset checks
./yact docker build g1-sim       # build the deploy image (first run; --force to rebuild)
```
The first `./yact` may offer to create a local `.venv` for its host deps — accept it.

### 2. Wire up the network
Connect the robot to the PC over Ethernet and give the PC a static IPv4 on the robot's
subnet: address `192.168.123.x` (any free host, e.g. `192.168.123.222`), mask
`255.255.255.0`. The robot is `192.168.123.164` by default. Then verify:
```bash
ip link                    # find the wired interface name (e.g. enp3s0) to pass to -n
ping 192.168.123.164       # must reply before deploying
```

### 3. Provide Jetson credentials (for localization)
Fast-LIO is launched on the robot's Jetson over SSH:
```bash
export YACT_JETSON_PASSWORD=...   # Jetson SSH password (user 'unitree' by default)
```
The `lio` image is staged onto the Jetson automatically the first time — pulled from the
registry, or built locally and shipped over SSH if the registry is unreachable. Override
`YACT_JETSON_HOST` / `YACT_JETSON_USER` if they differ from the defaults.

### 4. Prepare the robot
Power on the G1 and put it in a state ready for low-level control (motors enabled,
suspended or in a safe stance). Deploy releases the built-in motion/sport mode and takes
low-level control on startup.

### 5. Deploy
```bash
./yact deploy -n enp3s0 --vr      # live VR teleop (Vuer WebXR)
# or
./yact deploy -n enp3s0 --wasd    # keyboard control (no headset)
```
Watch for these milestones, in order:
- `Successfully connected to the robot.` — DDS link to the G1 is up.
- `Localization: ✓ Fast-LIO running` — Jetson localization is live (or a clear `✗` + reason).
- the policy loads, the FSM graph prints, and the robot starts in **Damp** (compliant, safe).

For `--vr`, it also prints an `https://<lan-ip>:8012` URL.

### 6. Connect the headset (`--vr` only)
On a WebXR headset on the same LAN, open the printed URL, accept the self-signed cert
once, and tap **Passthrough**. Head + Quest/Touch controller poses stream back; wait for
`VR connected.`

### 7. Bring the robot up through the FSM
The teleoperation branch is **Damp → StartState → JustStand → Middle → DoTeleop**. Advance one node
at a time; teleoperation is live only in **DoTeleop**:

| Action | Keyboard | VR (right controller) |
|--------|:--------:|:---------------------:|
| Advance to next node | `1` | **B** |
| Damp / e-stop | `x` (or `0`) | **A** |
| Move / strafe (WASD mode only) | `W S` / `A D` | — |
| Turn left / right (WASD mode only) | `Q E` | — |
| Stop keyboard motion | **Space** | — |

Press `1` (or **B**) to step StartState → JustStand → Middle → DoTeleop. In **DoTeleop** the
headset/controllers (or WASD + QE) drive the robot; with `--dex3` the right trigger drives the
hand.

### 8. Stop
Press `x` (or VR **A**) to damp, then `Ctrl+C` to exit — this stops the FSM and closes the
robot link.

### Troubleshooting
- **`Localization: ✗ FAILED`** — rerun with `--debug` for the full launch log; check
  `YACT_JETSON_PASSWORD` and that `ping 192.168.123.164` replies. Force a relaunch with
  `--restart-localization`.
- **`authorization failed: no basic auth credentials`** (image staging) — the registry is
  unreachable, so the `lio` image is built locally instead. This needs `docker buildx`; on
  an amd64 host it cross-builds arm64 under QEMU — register it once with
  `docker run --privileged --rm tonistiigi/binfmt --install arm64`.
- **No VR poses / unreachable URL** — set `YACT_VR_HOST` to the PC's LAN IP (behind
  docker/NAT the container can't detect it).
- **Robot won't accept control** — ensure its built-in sport/service mode is off and no
  other low-level controller is running.

## Assets

Inference needs blobs under `assets/`:

| Required | Path |
|----------|------|
| JIT policy | `assets/checkpoints/default.pt` |
| MuJoCo scene | `assets/mujoco/g1_29dof_rev_1_0_custom_actuators/` |
| Floor texture (optional) | `assets/mujoco/g1_29dof_rev_1_0_custom_actuators/textures/floor.png` |
| FK URDF | `assets/fk/g1_fk.urdf` |
| T-pose VR replay | `assets/trajectories/t_pose_traj.json` |

`assets/trajectories/walk_forward.json` (optional VR replay) is generated by
`scripts/generate_walk_trajectory.py`.
`assets/tts/alerts/motor_temp_warning.wav` is generated by
`scripts/generate_alert_audio.py` (Kokoro TTS).

The assets are stored in ordinary Git. `./yact setup` verifies required files;
set `YACT_ASSETS_DIR` if you intentionally keep them elsewhere. Docker mounts
that directory at the normal in-container `assets/` path when it creates the
container. After changing or unsetting the override, run
`./yact docker stop g1-sim` (or `g1-sim-cpu`) before starting again so the mount
is recreated.

Startup uses the static `default_position` joint angles in
`lib/deploy/configs/g1.yaml`; no mocap trajectory is required for startup.
